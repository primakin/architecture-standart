### <a name="_u8xz25hbrgql"></a>**Нефункциональные требования**

| **№**  | Требование                                                                                                                                    |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| **R**  | **Надёжность (Reliability)**                                                                                                                  |
| R1     | Все сервисы (АБС, интернет-банк) должны работать 24/7, SLA 99,9                                                                               |
| R2     | Предусмотреть равномерное горизонтальное масштабирование                                                                                      |
| **P**  | **Производительность (Performance)**                                                                                                          |
| P1     | Отклик по всем операциям в интернет-банке должен быть максимально быстрым и занимать миллисекунды                                             |
| **+R** | **+ Ограничения (Restrictions)**                                                                                                              |
| +R1    | Данные, передаваемые с сайта, должны быть защищены шифрованием трафика                                                                        |
| +R2    | Работу с СМС желательно реализовать силами команды разработки банка, без привлечения подрядчика                                               |
| +R3    | В интернет-банке данные при передаче надо защитить механизмом шифрования                                                                      |
| +R4    | Используем технологии, которые уже есть в банке:<br>СУБД: MS SQL, Oracle<br>Веб-фреймворк: ASP.NET<br>Бэкенд: PHP, Java<br>Фронтенд: React.js |
| +R5    | Новые технологии должны быть совместимы с существующими платформами разработки                                                                |
| +R6    | Очереди сообщений - Kafka                                                                                                                     |
| +R7    | В рамках задачи открытия депозитов надо подумать о переводе интернет-банка на микросервисную архитектуру                                      |
| +R8    | Избежать прямой работы интернет-банка с API АБС                                                                                               |

1. Выбор технологий обоснован требованием **+R4** - используем те технологии, которые уже есть в банке.
2. Очередь сообщений в АБС обусловлена требованием **+R8** - избежать прямой работы интернет-банка с API АБС.
3. Kafka в качестве очереди сообщений - **+R6**.
4. Требованием **+R7** обосновано начало перехода на микросервисную архитектуру в интернет-банке.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
1. Для MVP, возможно, было бы дешевле развивать интернет-банк как монолит, отложив переход на микросервисную архитектуру.

**Недостатки, ограничения, риски**
1. Интернет-банк все еще имеет большую монолитную часть, в будущем это может создать риски масштабирования функционала и усложнить разработку.
2. Разработчики сообщили, что БД в АБС нагружена. Возможно, ее надо будет как-то разделять.
3. Для работы с АБС используется legacy desktop клиент - в перспективе потребуется его перевести на другой стек.
