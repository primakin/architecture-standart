| P1     | Кол-центры (внутренний и партнерский) должны получать ставки сразу же после их обновления в АБС |
| **+R** | **+ Ограничения (Restrictions)**                                                                |
| +R1    | Партнерский кол-центр не может вызывать API, но готов принимать файлы                           |
| +R2    | В партнерский кол-центр данные должны передаваться в зашифрованном виде                         |

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
На стороне партнерского кол-центра можно развернуть легковесный коннектор для интеграции с API банка:
1. Запускается как служба Windows/Linux в инфраструктуре партнера.
2. Не является полноценным API-сервером (не принимает входящие запросы).
3. Для получения ставок у банка вызывает тот же API, что и система кол-центра банка.
4. Полученные данные парсит и сохраняет в БД партнерского кол-центра.
   
**Недостатки, ограничения, риски**
- UC1: на случай недоступности АБС во время звонка клиента в системе кол-центра должен быть реализован периодический поллинг АБС с сохраненим актуальных ставок в локальную БД.
- UC2: использование файла для передачи ставок небезопасно, требует ручной обработки на стороне партнерского кол-центра, плохо масштабируется, может приводить к задержкам в получении актуальных ставок сотрудниками кол-центра.
